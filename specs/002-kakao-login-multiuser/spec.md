# Feature Specification: 카카오 간편로그인과 다중 사용자 지원

**Feature Branch**: `008-kakao-login-multiuser`

**Created**: 2026-11-05

**Status**: Draft

**Input**: User description: "아이디 패스워드 방식이 아닌 카카오 간편로그인 인증방식을 도입해줘 (개인 혼자만 사용하는것이 아닌 로그인한 유저 다수가 사용할수 있도록)"

## 배경

현재 플랫폼(기능 001)은 소유자 1명이 비밀번호로 로그인해 쓰는 구조다. 이 기능은 로그인 방식을 카카오 간편로그인으로
바꾸고, 카카오로 로그인한 여러 사용자가 각자 자기 계좌·보유 종목·AI 키·가이드 기록을 따로 관리하며 함께 쓸 수
있게 한다. 종목 정보와 시세는 모든 사용자가 공유한다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 카카오 계정으로 가입·로그인 (Priority: P1)

방문자는 "카카오로 시작하기" 버튼 하나로 처음 가입하고, 다음부터는 같은 버튼으로 로그인한다. 비밀번호를 만들거나
기억할 필요가 없다.

**Why this priority**: 로그인이 되지 않으면 어떤 기능도 쓸 수 없다. 기존 비밀번호 로그인을 대체하는 핵심이다.

**Independent Test**: 처음 보는 카카오 계정으로 로그인하면 새 사용자로 가입되어 빈 대시보드가 보이고, 로그아웃 후
같은 계정으로 다시 로그인하면 같은 사용자로 들어오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 방문자, **When** 아무 화면에 접근하면, **Then** "카카오로 시작하기" 버튼이 있는 로그인
   화면으로 이동한다. 비밀번호 입력란이나 최초 설정 화면은 없다.
2. **Given** 이 서비스에 처음 오는 카카오 사용자, **When** 카카오 로그인과 동의를 마치면, **Then** 새 사용자로
   가입되고 빈 대시보드(계좌 추가 안내)가 보인다.
3. **Given** 이미 가입한 사용자, **When** 다시 카카오로 로그인하면, **Then** 새 사용자가 생기지 않고 이전에 만든
   계좌·보유 종목이 그대로 보인다.
4. **Given** 카카오 로그인 화면에서 사용자가 동의를 취소한 경우, **When** 서비스로 돌아오면, **Then** 로그인되지 않고
   "카카오 로그인이 취소되었습니다"와 다시 시도 버튼이 보인다.
5. **Given** 로그인한 사용자, **When** 로그아웃하면, **Then** 이 서비스의 세션만 끝나고 로그인 화면으로 돌아간다.
6. **Given** 로그인한 사용자, **When** 7일 동안 활동이 없으면, **Then** 세션이 만료되어 다시 로그인해야 한다.

---

### User Story 2 - 사용자별 데이터 분리 (Priority: P1)

여러 사용자가 동시에 쓰더라도 각자는 자기 계좌·보유 종목·AI 키·가이드 기록만 보고 바꿀 수 있다. 다른 사용자의
데이터는 화면에 보이지 않고, 주소를 직접 입력해도 접근할 수 없다.

**Why this priority**: 다중 사용자 서비스에서 데이터가 섞이거나 남에게 보이면 개인 투자 정보와 AI 키가 노출되는
심각한 문제가 된다. 로그인과 함께 반드시 갖춰야 한다.

**Independent Test**: 사용자 A와 B가 각각 계좌와 보유 종목을 만든 뒤, 서로의 대시보드에 상대 데이터가 없고 A가 B의
보유 종목·가이드·계좌 주소로 직접 요청하면 "찾을 수 없음"이 되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 사용자 A와 B가 각자 계좌를 가진 상태, **When** A가 대시보드를 열면, **Then** A의 계좌와 보유 종목만 보인다.
2. **Given** B의 보유 종목·계좌·가이드 기록, **When** A가 그 항목을 보거나 수정·삭제하려고 직접 요청하면, **Then**
   존재하지 않는 항목과 같은 "찾을 수 없음" 응답을 받고 B의 데이터는 바뀌지 않는다.
3. **Given** A와 B가 같은 계좌 이름 "키움 일반"을 쓰려는 경우, **When** 각자 계좌를 만들면, **Then** 둘 다 만들 수
   있다(계좌 이름 중복 검사는 사용자별).
4. **Given** A가 AI 키를 등록한 상태, **When** B가 AI 설정 화면을 열면, **Then** B에게는 "키 필요"로 보이고 A의 키로
   B의 가이드가 요청되지 않는다.
5. **Given** A와 B가 같은 종목(삼성전자)을 보유, **When** 둘이 대시보드를 보면, **Then** 같은 현재가가 보이지만
   평단가·수량·평가손익은 각자 자기 값이다.

---

### User Story 3 - 사용자별 한도 (Priority: P2)

계좌 2개, 보유 종목 20개, 종목별 하루 가이드 2회 한도는 사용자마다 따로 적용된다. 한 사용자가 한도를 다 써도 다른
사용자에게는 영향이 없다.

**Why this priority**: 한도가 전체 서비스 기준으로 남아 있으면 한 사용자가 다른 사용자의 사용을 막게 된다. 데이터
분리 다음으로 중요하다.

**Independent Test**: A가 삼성전자 가이드를 오늘 2회 받은 뒤에도 B는 삼성전자 가이드를 2회 받을 수 있고, A가 계좌
2개를 만든 뒤에도 B는 계좌를 만들 수 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** A가 계좌 2개를 가진 상태, **When** B가 계좌를 만들면, **Then** 만들어진다. A가 세 번째 계좌를 만들면
   거부되고 상한 안내가 보인다.
2. **Given** A가 오늘 삼성전자 가이드를 2회 받은 상태, **When** B가 삼성전자 가이드를 요청하면, **Then** B는 남은
   2회로 요청할 수 있다.
3. **Given** A가 같은 종목을 계좌 2개에 보유, **When** A가 가이드를 요청하면, **Then** 두 계좌를 합쳐 하루 2회다
   (기존 규칙을 사용자 안에서 유지).

---

### User Story 4 - 회원 탈퇴 (Priority: P3)

사용자는 설정에서 탈퇴할 수 있다. 탈퇴하면 그 사용자의 계좌·보유 종목·AI 키·가이드 기록이 모두 삭제되고, 카카오
연결도 끊긴다. 같은 카카오 계정으로 다시 로그인하면 새 사용자로 처음부터 시작한다.

**Why this priority**: 여러 사람이 가입하는 서비스는 개인정보를 스스로 지울 수단을 제공해야 한다. 핵심 사용 흐름은
아니므로 P3다.

**Independent Test**: 데이터가 있는 사용자가 탈퇴 확인 후 탈퇴하면 로그아웃되고, 같은 카카오 계정으로 다시 로그인하면
빈 대시보드가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 계좌·보유 종목·AI 키·가이드 기록이 있는 사용자, **When** 탈퇴 버튼을 누르면, **Then** 되돌릴 수 없다는
   확인 단계가 나온다.
2. **Given** 확인을 마친 경우, **When** 탈퇴가 처리되면, **Then** 그 사용자의 모든 데이터가 삭제되고 로그아웃되며
   카카오 연결이 해제된다.
3. **Given** 탈퇴한 카카오 계정, **When** 다시 로그인하면, **Then** 새 사용자로 가입되고 이전 데이터는 보이지 않는다.

---

### Edge Cases

- 배포 후 첫 카카오 로그인 사용자 두 명이 동시에 가입하면, 기존 데이터는 둘 중 한 명에게만 넘어가야 한다.

- 카카오 인증 서버가 응답하지 않거나 오류를 주면 로그인되지 않고 "카카오 로그인에 실패했습니다. 잠시 후 다시
  시도해 주세요"가 보인다.
- 로그인 요청과 콜백이 짝이 맞지 않으면(위조·재사용된 요청) 로그인을 거부한다.
- 카카오 쪽에서 사용자가 이 서비스와의 연결을 끊었더라도, 이미 발급된 세션은 만료될 때까지 유지된다. 다음 로그인 때
  다시 동의를 받는다.
- 닉네임 제공에 동의하지 않은 사용자는 "카카오 사용자"처럼 기본 표시 이름을 쓴다.
- 같은 사용자가 여러 브라우저·기기에서 동시에 로그인할 수 있다.
- 탈퇴 처리 중 카카오 연결 해제가 실패해도 서비스 데이터 삭제와 로그아웃은 끝내고, 연결 해제는 나중에 다시 시도한다.
- 사용자 A가 가이드를 요청한 뒤 결과가 나오기 전에 탈퇴하면, 진행 중인 가이드는 결과를 저장하지 않고 버린다.
- 진행 중인 가이드 화면 주소를 다른 사용자가 열면 "찾을 수 없음"이다.

## Requirements *(mandatory)*

### Functional Requirements

**인증**

- **FR-001**: 시스템은 카카오 간편로그인만으로 가입과 로그인을 제공해야 한다. 기존 비밀번호 로그인, 최초 설정
  화면, 로그인 실패 잠금은 제거한다.
- **FR-002**: 시스템은 카카오 사용자 식별자로 사용자를 구분해야 한다. 처음 로그인한 카카오 사용자는 자동으로
  가입되고, 이후 로그인은 같은 사용자로 연결된다.
- **FR-003**: 카카오 계정이 있는 사람은 누구나 가입할 수 있다. 허용 목록이나 전체 사용자 수 상한은 두지 않는다.
- **FR-004**: 시스템은 카카오에서 필수로 받는 정보를 사용자 식별자로 한정하고, 닉네임은 선택 동의로 받아 화면 표시에만
  쓴다. 이메일·전화번호 등 다른 개인정보는 요청하지 않는다.
- **FR-005**: 로그인 요청은 위조와 재사용을 막아야 한다. 요청과 콜백이 짝이 맞지 않으면 거부한다.
- **FR-006**: 로그인 세션은 7일 동안 활동이 없으면 만료되어야 한다(기존 기준 유지). 로그아웃은 이 서비스의 세션만
  끝낸다.
- **FR-007**: 화면 상단에 로그인한 사용자의 표시 이름과 로그아웃이 보여야 한다.

**사용자별 데이터 분리**

- **FR-008**: 계좌, 보유 종목, AI 공급자 키, 가이드용 공급자 선택, 가이드 요청·기록은 사용자 소유여야 한다. 사용자는
  자기 데이터만 조회·생성·수정·삭제할 수 있다.
- **FR-009**: 다른 사용자의 항목에 대한 모든 요청(조회, 수정, 삭제, 가이드 요청, 진행 상태 확인)은 존재하지 않는
  항목과 같은 응답을 받아야 한다. 다른 사용자의 데이터 존재 여부가 드러나면 안 된다.
- **FR-010**: 계좌 이름 중복 검사는 사용자 안에서만 한다.
- **FR-011**: 종목 정보, 시세, 장 운영 정보, 수급 데이터는 모든 사용자가 공유한다. 시세 갱신 대상은 모든 사용자의
  보유 종목을 합친 목록이다.
- **FR-012**: AI 가이드는 요청한 사용자 자신의 AI 키와 선택한 공급자로만 생성해야 한다.

**사용자별 한도**

- **FR-013**: 계좌 최대 2개, 보유 종목 최대 20개는 사용자마다 적용한다.
- **FR-014**: 종목별 하루 가이드 2회는 사용자마다 적용한다. 같은 사용자가 같은 종목을 여러 계좌에 보유하면 합산한다.
  동시 요청에서도 사용자별 한도를 넘지 않아야 한다.

**탈퇴**

- **FR-015**: 사용자는 확인 단계를 거쳐 탈퇴할 수 있어야 한다. 탈퇴하면 그 사용자의 계좌, 보유 종목, AI 키, 공급자
  선택, 가이드 요청·기록을 모두 삭제하고 카카오 연결을 해제한다.
- **FR-016**: 탈퇴한 카카오 계정으로 다시 로그인하면 새 사용자로 가입된다.

**기존 데이터**

- **FR-017**: 기능 001에서 만든 기존 소유자 데이터(계좌, 보유 종목, AI 키, 공급자 선택, 가이드 기록)는 이 기능을
  배포한 뒤 **처음으로 카카오 로그인에 성공한 사용자**에게 한 번만 넘긴다. 이후 가입하는 사용자는 빈 상태로 시작한다.
  기존 데이터가 없으면 넘길 것도 없다.

### Key Entities

- **사용자(User)**: 카카오로 가입한 사람. 카카오 사용자 식별자(고유), 표시 이름(닉네임, 선택), 가입 시각, 마지막
  로그인 시각, 가이드용으로 선택한 AI 공급자를 가진다. 기존 "소유자"를 대체한다.
- **계좌·보유 종목**: 사용자에게 속한다. 계좌 이름은 사용자 안에서 유일하다.
- **AI 공급자 키**: 사용자에게 속하며, 사용자마다 공급자별로 하나씩 가진다.
- **가이드 요청·기록**: 사용자에게 속한다. 하루 한도는 사용자·종목·날짜 단위로 센다.
- **종목·시세·장 운영 정보·수급**: 사용자와 무관한 공유 데이터다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 처음 방문한 사용자가 카카오 로그인 버튼을 누르고 동의를 마친 뒤 대시보드를 보기까지 30초 이내다(카카오
  화면 조작 시간 포함).
- **SC-002**: 가입한 사용자의 재로그인은 버튼을 누른 뒤 5초 이내에 대시보드가 보인다(카카오에 이미 로그인된 경우).
- **SC-003**: 다른 사용자의 계좌·보유 종목·AI 키·가이드 기록에 대한 접근 시도는 100% 거부되며, 자동화된 검사에서
  사용자 간 데이터 노출이 0건이다.
- **SC-004**: 동시에 활동하는 사용자 50명 환경에서도 기존 화면 응답 시간 목표(대시보드 2초 이내 등)를 지킨다.
- **SC-005**: 사용자별 하루 가이드 한도는 같은 사용자의 동시 요청 20건에서도 2건을 넘지 않는다(100회 반복).
- **SC-006**: 탈퇴 후 그 사용자의 개인 데이터가 서비스 저장소에 남지 않는다(검사 0건).

## Assumptions

- 카카오 개발자 애플리케이션(앱 키, 등록된 리다이렉트 주소)은 운영자가 미리 준비한다. 앱 키는 운영 설정으로 받는다.
- 로그인은 카카오 계정만 지원한다. 다른 소셜 로그인과 이메일 가입은 이번 범위가 아니다.
- 관리자 화면(사용자 목록, 강제 탈퇴 등)은 이번 범위가 아니다.
- 화면은 지금처럼 서버 렌더링 웹 앱이며, 모바일 앱의 카카오 SDK 로그인은 범위가 아니다.
- 토스증권 시세 연동은 계속 서비스 운영 설정(하나의 키)으로 하며, 사용자 수가 늘어도 보유 종목 합계가 시세 호출 한도
  안에 들어간다고 가정한다(사용자당 보유 종목 최대 20개).
- AI 키 암호화 저장, 키 비노출(기능 001 SC-009) 규칙은 사용자마다 그대로 적용된다.
- 카카오 로그아웃(카카오 계정 자체 로그아웃)은 하지 않고, 이 서비스 세션만 끝낸다.
- 공개 가입(FR-003)으로 사용자 수에 상한이 없으므로, 시세 호출량은 "사용자당 보유 종목 20개 × 사용자 수"만큼 늘 수
  있다. 운영 규모가 토스증권 호출 한도에 가까워지면 별도 조치(상한 도입 등)가 필요하다.
- 기존 데이터 이전(FR-017)은 배포 직후 기존 소유자(운영자)가 가장 먼저 카카오로 로그인한다는 운영 절차를 전제로 한다.
  다른 사람이 먼저 로그인하면 그 사람에게 넘어가므로, 배포 공지 전에 운영자가 로그인을 마쳐야 한다.
